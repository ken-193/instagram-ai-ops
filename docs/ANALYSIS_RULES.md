# ANALYSIS_RULES — 投稿後の分析

## タイミング
`insights` ワークフローが6時間ごとに動き、公開から **24時間・72時間・7日** を過ぎた投稿の指標を1回ずつ取得します（取り逃しても次の実行で取得）。

## 取得する指標（Instagram API with Instagram Login のメディアインサイト）
| 指標 | 内容 |
|---|---|
| `views` | 再生数 |
| `reach` | リーチ |
| `likes` / `comments` / `shares` / `saved` | いいね・コメント・シェア・保存 |
| `total_interactions` | 合計インタラクション |
| `ig_reels_avg_watch_time` | 平均視聴時間（ミリ秒） |
| `ig_reels_video_view_total_time` | 合計視聴時間（ミリ秒） |

- APIが返さない指標（例: フォローへの貢献、秒単位の視聴維持率）は **欠損（—）のまま** 記録し、推測で補完しません。
- 指標名はMetaの仕様変更で廃止・改名されることがあります。取得できなくなった指標は欠損になり、他の指標の取得は続けます。

## 一緒に記録する制作情報（metadata.json）
投稿日時、尺、冒頭フック、分類、徳島オチのタイプ、制作時間（build_seconds）、制作コスト（cost_usd）。

## 比較の観点
- どの仮説・分類がリーチ／再生を取ったか
- どのフックが強かったか（再生数・平均視聴時間）
- 平均視聴時間 ÷ 尺 が低い投稿 → 中盤の展開で離脱した可能性（※APIでは秒単位の離脱位置は取得できないため「可能性」に留める）
- どの徳島オチがコメント・シェアを生んだか（エンゲージメント率 = (いいね+コメント+シェア+保存)/リーチ）
- 制作時間とコストの効率

## 判断のルール
- **同じグループが5本未満のうちは傾向と断定しない**（レポートに「参考値・サンプル不足」と表示）。
- 投稿時間帯・曜日・季節などの交絡要因を注記する。

## 次回企画への反映
1. Claude Codeは企画前に `reports/latest.md` と `reports/learnings.json` を読む。
2. 5本以上のデータがあるグループのみ、企画スコアの判断材料にする（例: コメントが伸びる徳島オチのタイプを候補に必ず1つ含める）。
3. 平均視聴が尺の50%未満の投稿があれば、冒頭3秒と中盤のテンポ改善を台本作成時の注意点に入れる。
4. 反映した内容は企画評価表（ideas/*.md）の「選定理由」に書く。

レポートは `08_分析・改善レポート/report_YYYYMMDD.md` に保存されます。
