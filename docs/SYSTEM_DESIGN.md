## 1. 各サービスの役割

| 要素 | 採用 | 役割 |
|---|---|---|
| Claude Code（クラウド） | ✅ | 企画・リサーチ・台本作成、コード開発・修正。**常時稼働サーバーとしては使わない**（セッションは使い捨てのコンテナ） |
| GitHub Actions | ✅ 司令塔 | 定期実行・制作・承認処理・公開・インサイト取得・エラー通知。秘密情報は GitHub Secrets で管理 |
| GitHub リポジトリ | ✅ | コード、台本、**承認・公開状態（state/posts/*.json）**。全状態遷移がコミット履歴として残る |
| GitHub iPhoneアプリ | ✅ | プッシュ通知、承認コマンド、手動実行、レポート閲覧 |
| Google Drive | ✅ | 完成動画・台本・出典・レポートの保管とiPhoneでの再生 |
| 動画制作 | ✅ プログラム生成 | Pillow + ffmpeg による図解アニメーション（地図・天体・数値・渦）。費用0円、決定的に再現可能 |
| 動画生成AI（Veo等） | ⏸ 将来 | 印象的な1〜2カットだけ追加する用途で検討。現在は `max_ai_video_seconds_per_post: 0` で無効 |
| 音声合成 | ✅ 音読さん（ondoku3.com・声「Sam」を検証中） / Gemini・Open JTalk（予備） | 試作は無料オフライン音声。より自然な音声は Google Chirp 3 HD に切替可能（実装済み・未検証） |
| BGM・効果音 | ✅ コード生成 | 第三者音源を使わないため利用条件の問題が発生しない |
| Muse | ✅ 投稿担当 | Drive `11_Muse投稿キュー` から承認済み動画を引き取りInstagramへ投稿（MUSE_HANDOFF.md） |
| Instagram API | ⏸ 予備 | 直接投稿・インサイト取得のコードは実装済み・未検証。`config/publishing.json` の mode を `api` にすると使用 |
| 通知 | ✅ GitHub通知 / 任意で ntfy | 承認依頼・公開完了・エラー |
| n8n Cloud | ❌ 不採用（代替候補） | GitHub Actions で同じことが追加費用なしでできるため |

## 2. 連携方式

```
[Claude Code セッション] --git push / PR--> [GitHub main]
        |                                        |
        | (script.json 追加・更新)                 v
        |                            [Actions: produce] --OAuth--> [Google Drive 06_承認待ち]
        |                                        |-- Issue作成 --> [GitHubアプリ通知] --> あなた
        |                                                                      |
        |                                     /approve コメント <---------------+
        |                                        v
        |                            [Actions: approval] state= approved（sha256固定）
        |                                        v
        |                            [Actions: publish] Driveから取得→sha256照合→11_Muse投稿キューへコピー→[Muse]→Instagram
        |                                        v
        |                            [Actions: insights 6h毎] → reports/ → Drive 08
        +-- 次回企画時に reports/latest.md と learnings.json を読む
```

- **承認状態はサーバー側（gitの状態ファイル）で管理**。通知の誤タップ・二重送信・再実行があっても、状態遷移表（`pipeline/state.py`）で許可された操作しか通らない。
- **承認はファイルのsha256に紐づく**。承認後に動画が差し替わった場合は公開しない。
- **公開は「状態を記録→API呼び出し」の順**。途中で失敗したら `publish_unknown` にして通知し、自動再投稿はしない。手動再実行時はコンテナの状態を照合（FINISHEDなら同じコンテナを公開＝重複しない、PUBLISHEDなら投稿を探して記録）。
- Driveの共有リンクはInstagramの動画URLとしては使わない。Instagram の **resumable upload（rupload.facebook.com）** でActionsから動画ファイルを直接送る設計のため、一時配信用ストレージは不要。

**音読さん（2026-10-29 採用方針）**: ナレーションは音読さん（ondoku3.com）のAPIで生成。指定の声「Sam」は `en-HK-SamNeural`（英語・香港の男性音声）で、日本語を読めるかは比較サンプルで確認する。無料プランは月ごとの文字数上限あり（1本約400〜500文字）。上限超過時は案内音声が返るため、エラーとして扱い使用しない。再レンダリングで文字数を消費しないよう、音声はActionsのキャッシュで再利用。

### できないこと・注意点
- **このClaude Codeクラウドセッションからは Instagram / Google API / 多くの外部サイトに接続できない**（環境のネットワーク制限）。本番処理は GitHub Actions で行う設計にしてある。
- Instagramは**プロアカウント（ビジネス/クリエイター）**が必要。個人アカウントではAPI投稿不可。
- Instagramの長期トークンは60日で失効 → `token-refresh` で自動更新（`SECRETS_PAT` 設定時）。
- Googleの OAuth アプリを「テスト」状態のままにすると更新トークンが7日で失効する → 「本番」に切り替えて使う（ENV_TEMPLATE参照）。
- 公開上限: アカウントごとに24時間あたりの公開数上限あり（二次情報では50件）。公開前に `content_publishing_limit` を確認する実装。

## 6. Museについて

投稿は Muse が担当します（2026-10-29 方針決定）。
- 受け渡し: 承認済みの版だけを Drive `11_Muse投稿キュー` に `IG-xxx.mp4 / .txt / .jpg` としてコピー。Museはこのフォルダだけを監視する。
- 完了記録: 投稿後に Issue へ `/posted URL`。キューのファイルは投稿済みフォルダへ移動し、再投稿を防ぐ。
- Museの仕様（監視方法・必要なファイル形式・投稿URLの通知可否・分析機能）は公開情報では確認できていないため、判明次第 `config/publishing.json` と手順を合わせる。
- 詳細: MUSE_HANDOFF.md

## 7. 認証情報の管理方針
- 秘密情報は **GitHub Secrets のみ**に保存。リポジトリ・Drive・ドキュメントには書かない（ENV_TEMPLATE.md は名前と用途だけ）。
- Actionsの各ジョブは必要な秘密情報だけを受け取る（制作ジョブにはInstagramトークンを渡さない）。
- 承認者は `APPROVER_LOGIN`（既定はリポジトリのオーナー）。他のユーザーのコメントは無視。

## 8. エラー発生時の対応
| 事象 | 自動対応 | あなたの対応 |
|---|---|---|
| 制作・品質チェック失敗 | 承認待ちに出さない／エラーIssue＋通知 | 内容を確認し、Claude Codeで修正依頼 |
| 再レンダリング上限 | 停止（費用暴走防止） | 原因確認後 `state/posts/<id>.json` の回数をリセット |
| 公開途中の失敗 | `publish_unknown` で停止・通知。再投稿しない | Instagramアプリで公開有無を確認 → publish を手動実行（照合して再開） |
| トークン失効 | 通知 | ENV_TEMPLATEの手順で再発行 |
| Drive/Instagram API障害 | ジョブ失敗＋通知 | 時間をおいて再実行 |
