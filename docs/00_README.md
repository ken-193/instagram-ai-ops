# もしもAI検証 — Instagram Reels 自動運用システム

「もしも〇〇が〇〇になったら？」をAIが検証し、壮大なアニメーションで描いて、最後は徳島に着地するリール動画を、
**iPhoneから指示 → AIが制作 → iPhoneで確認・承認 → 自動公開 → 自動分析** の流れで運用するためのプロジェクトです。

- コード・状態管理: GitHub `ken-193/instagram-ai-ops`（非公開リポジトリ）
- 保存先: Google Drive `instagram_post_reel`（このフォルダ）

> 補足: 指示書では保存先名が `instagram_reel_post` でしたが、Drive上に実在したのは `instagram_post_reel`（語順違い・作成直後で空）でした。
> 新しいルートフォルダは作らず、このフォルダを唯一の保存先として使っています。名前を変える場合はDrive上で改名するだけでOKです（IDで管理しているため動作に影響しません）。

## システム全体の構成

```
iPhone
 ├─ Claude アプリ（Claude Code）……… 企画20案→選定→リサーチ→台本→試作レンダリング→GitHubへ反映
 ├─ GitHub アプリ ……………………… 承認依頼の通知・/approve /revise /reject・手動実行・レポート閲覧
 └─ Google Drive アプリ ……………… 完成動画の再生・台本/出典/レポートの閲覧

GitHub Actions（クラウドで常時稼働・無料枠）
 ├─ produce   台本→ナレーション→アニメーション描画→MP4→品質チェック→Drive 06_承認待ち→承認依頼Issue
 ├─ approval  オーナーのコメントだけを受け付け、承認状態をサーバー側（git）で記録
 ├─ publish   承認済み かつ 承認時と同一ファイル の場合のみ Drive「11_Muse投稿キュー」へ受け渡し → Museが投稿
 ├─ insights  6時間ごとに 24h/72h/7d のインサイトを取得→分析レポート→Drive 08
 └─ token-refresh  Instagramトークンを月2回更新
```

## iPhoneからの操作方法

| やりたいこと | 操作 |
|---|---|
| 新しい動画を作る | Claudeアプリ → Claude Code → このリポジトリ → 「次の動画を1本作って」 |
| 既存の台本で作り直す | GitHubアプリ → Actions → produce → Run workflow → 投稿IDを入力 |
| 完成通知を受ける | GitHubアプリの通知（承認待ちIssueがあなたに割り当てられます）。任意でntfyアプリにも通知 |
| 動画を確認する | 通知のIssue内のDriveリンク → Driveアプリで再生 |
| 承認する | Issueに `/approve` と返信 → 動画が `11_Muse投稿キュー` に置かれ、Museが投稿 |
| 投稿完了を記録する | Museで投稿後、Issueに `/posted 投稿URL` と返信 |
| 修正を頼む | Issueに `/revise 冒頭をもっと速く` のように返信 → Claude Codeで「IG-xxxの修正依頼を反映して」 |
| 却下する | Issueに `/reject 理由` と返信（公開されません） |
| 分析を見る | GitHubアプリで `reports/latest.md`、またはDrive `08_分析・改善レポート` |

## 制作から投稿・分析までの流れ

1. **企画**: 20案以上を10項目で採点（重み付き）→上位3案を比較→1案選定。過去企画との類似度で重複を減点。
2. **リサーチ**: 公的機関・研究機関を優先。主張ごとに「確認済み/仮定/推定/フィクション」を付け、出典URLと計算方法を記録。
3. **台本**: `script.json`（機械用・スキーマ検証あり）→ `script.md`（人間用）を自動生成。
4. **制作**: ナレーション音声→尺を自動計算→アニメーション描画（月・地図・渦潮などのプログラム生成）→BGM/効果音（コードで生成・権利問題なし）→MP4。
5. **品質チェック**: コーデック・解像度・尺・音量(-14 LUFS)・黒画面・フリーズ・字幕安全領域・出典・クレジットを自動判定。不合格なら承認待ちに出さない。
6. **承認**: Drive 06 へ保存→GitHub Issueで通知→ `/approve` されたものだけ公開。
7. **投稿**: 承認済みの版だけを `11_Muse投稿キュー` にコピー → Museが投稿 → `/posted URL` で記録し、キューから移動（再投稿防止）。
8. **分析**: 24h/72h/7dで取得→レポート→次回企画の評価に反映（データが少ないうちは傾向と断定しない）。
