# CLAUDE.md — 世界の仕様外｜3Dアニメーション制作ルール

このフォルダ（`studio3d/`）は、Instagramアカウント「世界の仕様外」の3Dアニメーション（Blender）制作ライン。
iPhoneから「テーマ」を受け取ったら、このルールに従って 企画 → 台本 → 絵コンテ → Blender Python → レンダリング → Google Drive保存 まで行う。
（既存の2D/2.5D投稿システム「もしもAI検証」はリポジトリ直下の CLAUDE.md。承認・Muse投稿の仕組みはそちらにある）

## 1. コンセプト
- アカウント名：**世界の仕様外**　コンセプト：**世界のルールを、映像で壊す。**
- 基本形式：「もしも〇〇が〇〇になったら？」
- 誰もが分かる身近なテーマから始め、展開ごとに映像のスケールを段階的に規格外にする。
- 最後は予想外のシュールなオチ、または地域要素へ自然につなげる。**地域要素は冒頭から強調しない。**
- 地域・住民を揶揄しない。根拠のない断定をしない。事実を使う場合は公的資料で確認し、出典を残す。
- 著作権のあるキャラクター・ロゴ・既存作品の造形（例：特定の怪獣・ゲームのブロック表現）を再現しない。

## 2. 映像の基本仕様
- Instagram Reels / 縦 9:16 / **1080×1920** / **30fps** / 30〜50秒 / H.264 + yuv420p
- 実写ではなく高品質なCGアニメーション。リアルすぎず親しみやすいキャラクター。ブロック（ボクセル）状の造形は使わない。
- 光・影・奥行き・空気感のある背景（空：Nishita sky、太陽光＋エリアライト、反射のある水・光沢）。

## 3. 3Dビジュアルのルール
- 1つのプロジェクトでは、世界（地形・空・色）とキャラクター/主役オブジェクトを **共通のビルダー関数** で作る（`studio3d/lib/worlds.py` 等）。シーンごとに作り直さない＝一貫性を保つ。
- 主役の大きさは、民家・橋・木・人など **比較対象と同じ画面に入れて** 伝える。
- 色はシーン内で自然に（AgX・Punchy）。テロップ等の文字はこのラインでは入れない（後工程で追加予定）。
- 新しいキャラクターや主役は、まず静止画（ドラフト画質）で見た目を確認してからアニメーションに進む。

## 4. カメラワークのルール
- ストーリーとアクションに合わせて選ぶ。意味のない動きはしない。1シーン1つの主なカメラ意図。
- 使える手法（`studio3d/lib/core.py`）：
  - ローアングル（地面・水面すれすれ）／トラッキング（被写体と並走・先行）／オービット（`orbit()`）
  - ドリーイン・ドリーアウト（`lerp3` + `ease`）／俯瞰・クレーン（高度を補間）
  - スローモーション（`slowmo()` でアクション時間を遅らせる）／カメラシェイク（`shake()`、衝撃時は振幅を一瞬大きく）
- 同じアングルを長く続けない。シーンの切り替わりで構図（高さ・距離・向き）を変える。

## 5. 制作フロー（必ず分割して作る）
1. テーマ分析 → 必要な調査（公的機関・研究機関を優先。確認できない事実は使わない）
2. 企画 `01_planning/plan.md`
3. 台本 `02_script/script.md`（シーン・秒数・内容・ナレーション案）
4. 絵コンテ `03_storyboard/storyboard.md`（シーンごとのカメラ・被写体・狙い）
5. シーン仕様 `04_blender/project.json`（**1シーン5〜10秒**、合計30〜50秒）
6. シーンごとの Blender Python `04_blender/sNN_<内容>.py`
7. ドラフト確認：このセッションで `python studio3d/run.py render <project> <scene> --start N --end N+1 --quality draft` を数フレーム実行し、目視で品質確認（下記8）
8. 問題があれば原因を特定してスクリプトを修正 → 7へ
9. main に入れる（project.json の変更で `studio3d` ワークフローが起動）→ クラウドで全フレームを並列レンダリング → 結合 → 自動チェック → Google Drive 保存 → GitHub Issue「[3D完成]」で通知
10. 完成動画を Drive（iPhoneのDriveアプリ）で確認してもらう

## 6. ファイル命名規則
- プロジェクト名：`YYYYMMDD_<英小文字スネークケースの短い名前>`（例 `20261104_test_giant_fruit`）
- シーンID：`s01`, `s02` …／シーンファイル：`sNN_<内容>.py`（例 `s01_aerial_crane.py`）
- 出力：`<project>_sNN.mp4`（05_render）、`<project>_final.mp4`・`<project>_contact_sheet.jpg`・`qc.json`（07_final）
- 03_completed には `<project>.mp4` としてコピーする

## 7. プロジェクトフォルダ構成（リポジトリ＝Driveと同じ番号）
```
studio3d/projects/<project>/
  01_planning/  02_script/  03_storyboard/  04_blender/(project.json, sNN_*.py)
  05_render/  06_audio/  07_final/        ← 05〜07 は生成物（git には入れない）
```
Google Drive：`マイドライブ/instagram_reel_post/`（IDは `studio3d/config/drive.json`）
```
01_projects/<project>/01_planning … 07_final   02_assets/{sound_effects,music,models,textures}   03_completed/
```

## 8. 品質確認（各シーンのドラフトで必ず見る）
- キャラクター/主役の一貫性（形・色・大きさがシーン間で同じか）
- 世界観の統一（空・光・地形・色味）
- カメラワーク（意図どおりか、被写体が画面外に出ないか、建物や地面にめり込まないか）
- アニメーションの自然さ（速度・重さ・揺れ）
- レンダリング品質（白飛び・黒つぶれ・ノイズ・ちらつき）
- Reelsでの視認性（スマホの縦画面で主役が分かるか。上220px・下420pxはUIに隠れる）
結果と修正内容は `03_storyboard/storyboard.md` の末尾か作業報告に書く。確認していないことを「確認済み」と書かない。

## 9. Blender Python コーディングルール
- 各シーンファイルは次の3つだけを定義する：
  ```python
  SECONDS = 5.0                  # project.json の seconds と一致させる
  def build(ctx) -> dict: ...    # シーンを1回だけ構築し、動かす物を dict で返す
  def pose(ctx, h, t): ...       # 時刻 t の状態をセット（t だけで決まる純粋関数。乱数は seed 固定）
  ```
- キーフレームや物理ベイクに頼らず、**時刻 t から位置・回転・カメラを計算** する（フレームを分割して並列レンダリングするため）。物理演算は事前計算した関数（放物線、減衰振動など）で表現する。
- 共通処理は `studio3d/lib/` に置き、シーンファイルにコピペしない。
- 外部素材（モデル・テクスチャ・音）は `02_assets` に置き、ライセンスと出典を `01_planning/plan.md` に書く。

## 10. レンダリングルール（`studio3d/config/render.json`）
- エンジン：Cycles（CPU）＋デノイズ。GPUはない。
- `final`：1080×1920 ネイティブ・12サンプル（1フレーム約29秒）。`draft`：540×960 で描いて拡大（約7秒）。
- 30フレーム単位のチャンクに分けて GitHub Actions で並列実行（最大12並列）。10秒の動画で実行時間の合計は約150分（無料枠を使う）。
- 尺は合計30〜50秒まで。それを超える場合や、何度も作り直す場合は、無料枠の残りを考えて先にオーナーに確認する。

## 11. Google Drive 保存ルール
- 保存は `studio3d.assemble` が GitHub Actions 上で行う（認証情報は GitHub Secrets の `GDRIVE_*` のみ。コードやDriveに秘密情報を書かない）。
- 自動チェック（解像度・fps・尺・コーデック・黒画面・静止）に合格したものだけを保存する。
- 同名ファイルは新しい版として上書き（Driveの版履歴が残る）。既存ファイルの削除はしない。
- `03_completed` に置いた動画は投稿候補。Instagram への投稿は、既存の承認フロー（直下の CLAUDE.md）を通すまで行わない。
